### S18 的「数据文件夹自检」

防的是"文件夹里悄悄攒垃圾"。启动时跑一遍：

| 清理项 | 判断依据 |
|---|---|
| **孤儿图片文件** | `images\` 里没有被 `index.json` 中任何 `ImageEntry` 引用的 png → 删掉 |
| **残留的 `index.json.tmp`** | 上次写到一半崩溃留下的（正常路径下 `File.Replace` 会消费掉它） → 删掉 |
| **`index.unreadable-*.json` 留档** | **只保留最近 3 份**，更早的删掉。这类文件带时间戳，不做上限理论上能一直攒 |

> 前两项都是"删无可删就什么都不删"，第三项按文件名里的时间戳倒序排。

## 阶段 8 · 交付后的修正

> 用户实际用下来发现的问题。起因是**从资源管理器复制照片**这件事——
> 剪贴板里带的是"文件列表"格式，程序按 `文件 → 图片 → 文字` 的优先级把它当成了**文件**，
> 于是照片既被归到「文件」筛选里，卡片上也只显示一个文件图标、没有预览。

| 步骤 | 内容 | 完成标准 | 状态 |
|---|---|---|---|
| **S22** | 图片文件按"图片"归类 + 卡片显示缩略图预览（含 EXIF 方向纠正、老记录后台补图） | 复制 `.jpg` 后它在「图片」筛选下、不在「文件」下；卡片显示正的缩略图；重启后预览不丢 | ✅ |
| **S23** | 卡片内部的滚动条（三套模板统一，展开才出现、细滚动条） | 展开超过上限的内容时右侧出现细滚动条；收起和非溢出时不出现 | ✅ |
| **S23b** | 滚动条粗细调整：用户反馈太粗（外面列表那条不动） | 卡片里的滚动条明显比列表那条细；仍能拖动 | ✅ |
| **S23c** | 修"改了没生效"：`ScrollViewer.Resources` 里的隐式样式穿不进模板 → 改用卡片专用的 `Style.CardScrollViewer` | 逐像素量出卡片滚动条真的变细（改前是系统默认的 13px）；收起态无滚动条 | ✅ |
| **S23d** | 最终定 3px（1px 太细、2px 还想再粗一点，用户定稿） | 卡片里 3px、列表 4px；改宽度只需动 Thumb 上一个数字 | ✅ |

## 每一步的标准流程

1. **读规范**：读这一步相关的 `docs/` 文件（写代码前必读 [02-技术方案.md](02-技术方案.md)）
2. **在待办里标"进行中"**：`开发日志/待办.md`
3. **实现**
4. **自测**：对照 [06-测试验收.md](06-测试验收.md) 跑本步相关条目
5. **更新文档**：规范有变就同步改 `docs/`
6. **写日志**：在当天的 `开发日志/YYYY-MM-DD.md` 里记一笔
7. **在待办里标"已完成"**，向用户汇报，**停下等指示**
