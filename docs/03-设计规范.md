# 设计规范

> **每次改界面之前先读这份。** XAML 里**不允许写死颜色**，一律引用 `Themes/` 里的资源键。

## 设计基调

- 简洁、直观，不要花哨的动效和渐变
- 主色调**淡蓝**，但蓝色只用在"需要引起注意"的地方（选中、置顶、强调），大面积用中性色
- 贴近 Windows 10 的语言：方正、留白足、圆角克制
- 深色模式不是简单反色，而是重新配一套（见下文）

## 组件规范

### 卡片

```
┌────────────────────────────────────┐
│  [左侧]  内容区            📌  ⊗  │  ← 圆形按钮浮在右上角
│          ⏱ 时间                    │
└────────────────────────────────────┘
```

- **左侧**：文字卡片显示类型图标；图片卡片显示缩略图（最大 96 高 × 140 宽，等比缩放）；文件卡片显示文件/文件夹图标
- **内容区**：文字卡片最多显示 **3 行**，超出用省略号；有多行内容时行高 18
- **时间行**：相对时间，颜色用 `Brush.TextSecondary`
- **圆形按钮**：`Opacity` 平时 `0.35`，鼠标悬停到卡片上时变 `1`，**直接切换不做动画**
  - 之所以不做淡入淡出：WPF 里动画值的优先级高于触发器，退出动画会把 `Opacity` 钉死在 `0.35`，导致"已置顶"状态就再也显示不出来了。0.15 秒的过渡不值得拿正确性去换
  - **已置顶的卡片例外**：只要 `Pinned = true`，整组按钮的 `Opacity` 恒为 `1`。否则 `0.35` 的半透明会把"淡蓝实心图钉"和"灰色图钉"的差别盖掉，一眼看不出哪条被置顶
  - `📌` 置顶：未置顶时用 `Brush.IconIdle` 显示"置顶"图标；已置顶时用 `Brush.Accent` 显示"取消置顶"图标
  - `⊗` 删除：悬停时颜色变 `Brush.Danger` 且背景带一圈淡红（`#22E04545`）
- **内容区右侧要留出按钮宽度**（约 70px），避免长文字压到按钮下面

### 筛选胶囊

- 五个：`全部` `文字` `图片` `文件` `文件夹`
- 未选中：透明背景 + `Brush.TextSecondary` 文字
- 选中：`Brush.AccentSoft` 背景 + `Brush.Accent` 文字 + `Brush.Accent` 细边框
- 悬停（未选中时）：`Brush.CardHover` 背景
- 点击即切换，同一时刻只有一个选中

### 搜索框

- 左侧放大镜图标（用 `Brush.TextSecondary`）
- 有内容时右侧出现一个 `×` 清除按钮
- 聚焦时边框变 `Brush.Accent`
- 占位文字："搜索历史…"

### 分组标题

- "已置顶" / "最近" 两个分组，样式为小号 SemiBold + `Brush.TextSecondary`
- 分组为空时不显示该分组标题
- 搜索或筛选时**不显示分组**，直接平铺结果

### 底部状态栏

- 文案格式：`共 128 条 · 占用 214 MB · 保留 3 天`
- 字号 11，颜色 `Brush.TextSecondary`
- 上方有 `Brush.Separator` 分隔线

### 空状态

| 场景 | 文案 |
|---|---|
| 完全没记录 | 「还没有记录任何内容」+ 小字「复制点什么试试吧」 |
| 搜索无结果 | 「没找到包含"xxx"的内容」 |
| 筛选无结果 | 「当前筛选下没有内容」 |
| 筛选 + 搜索都无结果 | 「"图片"里没找到包含"xxx"的内容」 |

### 内容装不下时的渐隐与展开

**判定"装不下"的标准**

| 卡片类型 | 装不下的条件 |
|---|---|
| 文字 | 文字自然高度 > `54px`（3 行 × 18px 行高） |
| 文件 | 条目列表自然高度 > `58px`（约一行半） |
| 图片 | 缩略图区自然高度 > `82px`（一行 76 + 下间距 6） |

判定统一由 `ClampBehavior` 做：它挂在内容控件上，量出**没有上限时的真实高度**，
超过 `ClampHeight` 就把附加属性 `IsOverflowing` 置为 true。
三张卡片都绑这个属性来决定要不要显示渐隐和「展开」按钮，**不是**按条目个数硬判断——
条目个数判断不了"这个条目本身有多高"，一张只有两个超长文件名的卡片照样会溢出。

内容装得下时，**不显示渐隐、不显示展开按钮**（不是显示一个点不动的灰按钮）。

**渐隐怎么做**

用 `OpacityMask` 把内容底部渐变到透明，**不要用一张带颜色的渐变矩形盖上去**。
因为卡片背景会随主题变（`#FFFFFF` ↔ `#2B2B2B`）、还会随悬停变（`CardBg` → `CardHover`），
带颜色的遮罩得配四份色值，一定会漏。`OpacityMask` 让内容自己淡出、露出底下的卡片背景，天然适配所有情况。

```
渐变：StartPoint (0,0) → EndPoint (0,1)
  Offset 0.70  #FFFFFFFF
  Offset 1.00  #00FFFFFF
```

> 起点从 0.55 调到 0.70：裁剪高度正好是 3 行，从 55% 起淡意味着**整个第三行都在淡化区**里，
> 用户还没展开就已经看不清第三行写了什么。0.70 让第三行基本可读，只有最后一点点淡出——
> 既能读出"下面还有"，又不至于把已经显示出来的内容浪费掉。

**展开按钮**

- 位置：**时间那一行的右端**，不要浮在渐隐区上面（会和文字叠在一起看不清）
- 样式：小号文字链接 —— `展开 ∨` / `收起 ∧`，11px，颜色 `Brush.Accent`
- 图标用 `Icons.ChevronDown` / `Icons.ChevronUp`
- 展开后卡片恢复完整高度，渐隐取消，按钮文案变"收起"

**展开态也有高度上限**

| 状态 | 内容区最大高度 | 滚动条 |
|---|---|---|
| 收起 | `54px`（3 行） | 不出现，也不能滚 |
| 展开 | `300px`（约 16 行） | 超出时出现，**在卡片内部滚动** |

不加这个上限的话，展开一篇几千字的文章会让卡片比屏幕还高，"收起"按钮被顶到看不见的地方——
用户想收回去还得先滚很久。

**卡片内部的滚动条**（三种卡片模板统一）

| 项 | 值 |
|---|---|
| 样式 | `Style.CardScrollViewer`（卡片专用模板）+ `Style.ScrollBarSlim` + `Style.ScrollThumbSlim` |
| 可见宽度 | **3px**，无上下箭头 |
| 和外面列表的区别 | 外面列表用 `Style.ScrollViewer` + `Style.ScrollBar`，可见宽度 4px。卡片里的稍细一点 |
| 怎么生效 | 给卡片内部的 `ScrollViewer` 加 `Style="{StaticResource Style.CardScrollViewer}"`，由**它自己的模板**显式指定滚动条样式 |
| 可见性 | 收起 → `Hidden`；展开 → `Auto`。靠 `ExpandToScrollBarConverter` 转换 |

> ### ⚠️ 踩过的坑：隐式样式在这里不生效
>
> 最初是在每个卡片模板的 `ScrollViewer.Resources` 里放一条隐式 `ScrollBar` 样式
> （`<Style TargetType="ScrollBar" BasedOn="{StaticResource ...}" />`），
> 想让它只影响卡片内部的滚动条。
>
> **实测那样根本不起作用**：卡片里照样是系统默认滚动条——实测 **13px 宽**，
> 还带着系统配色的轨道（在深色主题下格外扎眼）。皮尺量出来的数字不会骗人：
> 我们那两条样式是 4px 和 3px，13px 哪条都对不上。
>
> 改成**在自己的 ControlTemplate 里显式指定 `Style`**（和外面列表 `Style.ScrollViewer` 是同一个套路）
> 之后立刻生效。模板里写死的样式不依赖隐式样式查找，一定能命中。
>
> **教训**：给模板生成的元素换皮肤时，别指望靠 `xxx.Resources` 里的隐式样式穿透过去。
> 要么像这里一样在自己模板里显式指定，要么放到 Window/App 级去（但那样影响面不可控）。

> **宽度是怎么做出来的**：写死在 Thumb 的 `Border` 上（`Width="3"` + `HorizontalAlignment="Center"`），
> **不用 `Margin` 去压**——靠边距凑宽度得算半个像素，会糊。
> 写死宽度后不管轨道多宽，画出来永远正正好这么宽，落在整数像素上不会发虚。
> 圆角给 1（给 3 会圆成两头尖的胶囊）。
>
> **改宽度只需要改 `Border` 上那一个数字**，不用动轨道宽度，也不用动那三处
> `Style.CardScrollViewer`。
>
> **`ScrollBar` 自己的 `Width` 仍旧是 8，别跟着改。** 那 8px 是**鼠标判定区**，
> 不是可见宽度；真改窄了就得戳进很细的缝里去拖，基本点不中。轨道是透明的，留多宽都看不出来。

> **收起态必须是 `Hidden`，不能是 `Auto`。** `Hidden` 不占位，内容的真实宽度才不受影响，
> `ClampBehavior` 量出来的高度才是"内容本来有多高"。换成 `Auto` 后滚动条会挤窄内容、
> 改变换行位置，卡片会平白判成装不下，多出一个点了没反应的「展开」按钮。
>
> 展开态用 `Auto` 而不是 `Visible`：内容刚好装得下时不该挂一条空槽出来。
>
> 注意内部这个 `ScrollViewer` **不要**套外面的 `Style.ScrollViewer`——那个模板是为虚拟化列表写的，
> 这里只需要换滚动条本身。

> 300 这个数是照着**最小窗口高度 420px** 定的：卡片内容 300 + 卡片上下留白和时间行约 60 +
> 顶部搜索筛选区约 110 + 状态栏约 30 ≈ 500，在窗口默认的 620px 里能完整放下，
> 缩到最小高度时"收起"按钮也还在。最初定的 420 太高，实测把"收起"顶出了可视区。

**滚轮要能接力**：卡片内部滚到头之后，继续滚滚轮应该接着滚外面的列表，
而不是"卡住不动"。所以内部滚动区要挂 `ScrollChainBehavior`：
  滚到顶还往上滚、或滚到底还往下滚时，把滚轮事件转交给外层的列表滚动区。

### 网址样式

- 文字内容被识别为网址时，那一段显示为 `Brush.Accent` + 下划线
- **只有网址本身可点**（点了用默认浏览器打开）；卡片其余部分仍然是"复制"
- 鼠标移到网址上要变成手型，明确"这里能点"

### 文件 / 文件夹卡片

**这份设计和最初设想不一样，改动理由写在下面，改回去之前先读一遍。**

```
┌──────────────────────────────────────────┐
│  ┌──┐ CLAUDE.md              4.4 KB  📌 ⊗│
│  │📄│ C:\Users\...\CLAUDE.md             │
│  └──┘                                    │
│  ┌──┐ docs                   53.9 KB     │
│  │📁│ C:\Users\...\docs      ← 淡出中    │
│  └──┘                                    │
│  6 分钟前                       展开 ∨   │
└──────────────────────────────────────────┘
```

**没有单独的"摘要行"。**
最初的设计是上面一行摘要（"报告.docx 等 3 项"），下面一块详情。做出来发现单个文件时
文件名会连说两遍——摘要里一次、详情里又一次。所以去掉摘要行，卡片直接就是条目列表。

**只有一个"展开 ∨"，没有另外一个"详情"下拉。**
需求里提过"加一个下拉按钮显示详情"。但详情展开和内容展开是同一个动作，
挂两个控件做同一件事只会让人不知道该点哪个。合并成一个：

| 状态 | 内容区最大高度 | 表现 |
|---|---|---|
| 收起 | `58px`（约一行半） | 露出一行半，底部渐隐，"展开 ∨" |
| 展开 | `300px` | 列出全部条目，超出在卡片内部滚 |

> 阈值 58 而不是 44（正好一行）：卡在 44 的话第二行被裁得一干二净，渐隐盖在空气上，
> 反而看不出"下面还有"。留半行让第二个条目的名字露一截再淡出，"还有更多"才传达到。

**单个条目时不显示"展开"**——详情本来就全部可见，按钮点了没反应更糟。

**每个条目一行**：左侧图标或缩略图 + 文件名 + 完整路径 + 右对齐的大小。

```
┌──────────────────────────────────────────┐
│  ┌──┐ 照片-001.jpg         8.7 MB    📌 ⊗│
│  │🖼│ C:\Users\...\照片-001.jpg          │
│  └──┘                                     │
│  13 分钟前                                │
└──────────────────────────────────────────┘
```

- **图片文件用缩略图代替图标**：`40 × 30` 的圆角小框，`Stretch=UniformToFill`。
  宽度固定 40 是为了让每一行的左边缘对齐——图片行和普通文件行的图标宽度不一样的话，列表看起来是歪的
- 没有缩略图的（普通文件、文件夹、生成失败的图片）照旧显示类型图标：
  文件夹 `Icons.Folder`、图片 `Icons.Photo`、其它 `Icons.Document`
- 缩略图是**复制时**生成的，存在 `images\{guid}_thumb.png`。
  这个功能上线**之前**存的老记录没有缩略图，卡片第一次显示出来时会在后台补生成
- 路径用 `Brush.TextSecondary`，11px，**可点击**（在资源管理器里定位到它）；悬停变 `Brush.Accent` 并加下划线
- **路径已经失效**时路径显示为 `Brush.TextDisabled`（灰掉），大小显示 `—`
- 文件夹的大小是**展开时才在后台算**的，算之前显示 `…`；遍历超过 5000 个文件或 2 秒就放弃，显示"较大"

| 部分 | 规范 |

| 分组标题 | 12px SemiBold，`Brush.TextPrimary`，上间距 16 |
| 说明小字 | 11px，`Brush.TextSecondary`，上间距 4 |
| 数字输入框 | 宽 72，高 28，圆角 4，右对齐，**只接受数字** |
| 快捷天数按钮 | 复用筛选胶囊的样式，但更小：高 22，圆角 11，字号 11 |
| 开关 | 44 × 22 的胶囊，关闭时底色 `Brush.CardBorder`、圆点在左；打开时底色 `Brush.Accent`、圆点在右 |
| 主题选择 | 复用筛选胶囊样式（同"全部/文字/图片"那排） |
| 普通按钮 | 高 30，圆角 4，边框 `Brush.CardBorder`，悬停底色 `Brush.CardHover` |
| 危险按钮（清空） | 同上，但文字用 `Brush.Danger`，悬停底色带淡红 |
| 底部按钮栏 | 右对齐，主按钮（保存）底色 `Brush.Accent`、白字；次按钮（取消）是普通按钮 |

**输入校验**：只允许输入数字（非数字按键直接吞掉）。点保存时再验一次范围：
期限 1–365、容量 50–10240。超范围就弹提示，并把输入框**恢复成上一次的有效值**，
不写盘、不关窗口。绝对不能让坏值写进 `settings.json`。

**"清空所有历史"必须二次确认**，而且要说清楚"置顶的也会一起删掉"。

**「关于」这一段**：版本号（12px，`Brush.TextPrimary`）+ **当前 exe 的完整路径**（`Style.Hint`，可换行）。

版本号取 assembly 的 `InformationalVersion`（会得到 `1.0.0`），并砍掉 `+` 之后的部分。
路径取 `Environment.ProcessPath`——**不能用 `Assembly.Location`**，单文件发布下它是空字符串。

> **为什么要显示 exe 路径**，而不是只写个版本号：
> 这台机器上同一个程序可能同时存在好几份（`bin\Debug\`、`bin\Release\`、`dist\`…），
> 长得一模一样、版本号也可能一样。用户报"我改了怎么没变"时，真正的原因往往就是双击到了旧的那一份，
> 光看版本号分辨不出来，路径才能一眼对上。
> **这个功能就是被这个坑推动加的**，见 [../开发日志/2026-10-06.md](../开发日志/2026-10-06.md)。

### 提示 / 确认对话框

**不用系统的 `MessageBox`**，用自己做的 `MessageWindow`。三个原因，都是实测出来的：

| 问题 | 说明 |
|---|---|
| 位置不可控 | MessageBox 会跑到屏幕外，而它不可拖拽，用户根本够不着 |
| 主题脱节 | 它是系统原生窗口，在深色主题下仍然是亮色的 |
| 按钮文案改不了 | 只能是"是/否"，而这里要说清楚"清空"这个动作不可逆 |

规范：

- 宽 380，高度自适应内容（`SizeToContent="Height"`），不可缩放
- 正文 13px、行高 20，最多占 4 行左右
- 按钮右对齐：左"取消"（普通样式）、右确认按钮
  - 普通确认用主按钮样式（`Style.Button.Primary`）
  - **不可逆的操作用危险样式**（`Style.Button.Danger`），而且按钮文案要写具体动作（"清空"）而不是笼统的"确定"
- **显示后要 `WindowPlacement.ClampToWorkArea` 夹回屏幕内**，和设置窗口一样
- `Esc` = 取消
- 关掉对话框后把焦点还给调用它的窗口，否则焦点会掉到桌面上

## 主题切换

- 设置里三选一：浅色 / 深色 / 跟随系统（默认跟随系统）
- **在设置里选好、点"保存"之后才生效**（不是一选中就变）。因为设置窗口有"取消"按钮，
  边选边生效的话"取消"就撤销不了主题了。
- 跟随系统时，**每次显示窗口**读一次注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` 的 `AppsUseLightTheme`（1 = 浅色，0 = 深色）
- 切换实现：替换 `Application.Current.Resources.MergedDictionaries` 里的主题字典，颜色自动刷新

## 颜色审计

改完界面要扫一遍有没有写死的颜色，否则深色模式一定会漏改：

```
grep -n '"#[0-9A-Fa-f]\{6,8\}"' *.xaml Themes/*.xaml
```

允许出现色值的地方只有三处：

1. `Themes/Light.xaml` / `Themes/Dark.xaml` —— 这两份本来就是配色表
2. `Themes/Controls.xaml` —— **不允许**，那里的颜色一律引用上面的资源键
3. `Converters/*.cs` 里的 `OpacityMask` 渐变 —— **例外**。遮罩只取 alpha 通道，
   RGB 填什么都不影响结果，所以写成白色是"无色"的意思，不是写死了一个颜色。
   代码里要注明这一点，免得下次有人当成漏改给"修"了

## 图标

- `Assets/app.ico`，**由 `工具/生成图标.ps1` 生成**，不要手改这个二进制文件
- 形状：淡蓝圆角方块 + 白色纸面 + 顶部深蓝夹子
- 必须包含 **16 / 24 / 32 / 48 / 64 / 256** 六个尺寸
  - 少了小尺寸，托盘里会糊；少了 256，资源管理器大图标视图会糊
  - **16 和 256 都用同样的比例画**，靠比例缩放在小尺寸下才不会走形
- 编码：16–64 用 BMP（兼容性好），256 用 PNG（BMP 格式能到 256KB）
- 同一个文件既是 exe 图标（`<ApplicationIcon>`），也是 WPF 资源（`<Resource>`），
  托盘从资源流里取 16×16 那张
