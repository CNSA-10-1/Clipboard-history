## 抗崩溃（重点回归）

剪贴板里放什么完全由别的程序决定，我们是在解析**不可信的外部数据**。
这一组是用来确认"坏数据不会弄死程序"的。

| 验证项 | 操作 | 期望结果 | 相关步骤 |
|---|---|---|---|
| ⭐ 序列化对象 | 往剪贴板放一个 .NET 序列化对象（见下方脚本） | 程序**不崩**；这次内容被跳过；`error.log` 里记一笔 | S9 |
| ⭐ 非标准图片格式 | 同上（那个载荷里装的其实是图片） | 不崩、不记，安静跳过 | S9 |
| 标准单图不受影响 | 紧接着用 `Clipboard.SetImage` 放一张标准位图 | 正常捕获（能存能显示），说明兜底没有把正常路径也吞掉 | S9 |
| 剪贴板被独占 | 某程序长时间占着剪贴板时复制 | 重试后成功或跳过，不崩 | S10 |
| 任意异常不致命 | 界面上任何一处抛未处理异常 | 记 `error.log` 后程序继续运行 | S20 |

<details>
<summary>复现用脚本（往剪贴板放 .NET 序列化对象）</summary>

```powershell
Add-Type -AssemblyName System.Drawing, System.Windows.Forms
$streams = New-Object 'System.Collections.Generic.List[System.IO.MemoryStream]'
foreach ($c in @('#4A9BE8','#E8A33D')) {
    $bmp = New-Object System.Drawing.Bitmap 300, 200
    $g = [System.Drawing.Graphics]::FromImage($bmp)
    $g.Clear([System.Drawing.ColorTranslator]::FromHtml($c)); $g.Dispose()
    $ms = New-Object System.IO.MemoryStream
    $bmp.Save($ms, [System.Drawing.Imaging.ImageFormat]::Png); $ms.Position = 0
    $streams.Add($ms); $bmp.Dispose()
}
$data = New-Object System.Windows.Forms.DataObject
$data.SetData('Bitmap', $streams.ToArray())
[System.Windows.Forms.Clipboard]::SetDataObject($data, $true)
```
</details>

## 性能基准

**用 Release 构建测**，Debug 的数字没有参考价值。测量脚本：`工具/测量性能.ps1`。

| 项目 | 期望 | 实测（500 条记录） |
|---|---|---|
| 冷启动（进程起到窗口可见） | < 2 秒 | 1.2 秒 ✅ |
| 常驻内存（**私有内存**） | < 80 MB | 58.9 MB ✅ |
| 打开窗口（已在运行时把窗口叫出来） | < 300 ms | 26 ms ✅ |
| 500 条记录时列表滚动 | 流畅 | 靠虚拟化保证（见下） |

> 内存看**私有内存**而不是工作集：工作集含 .NET 运行时和 WPF 程序集映射进来的共享页，
> 那部分不是这个程序能控制的，拿它当指标会永远超标。作为参考，工作集约 110 MB，
> 而空数据时也是 105 MB——说明列表本身几乎不占额外内存。

### ⚠️ 这一组必须配着"虚拟化还开着"一起看

S20 验收时发现过一个严重的性能问题：**自定义的 `ScrollViewer` 模板把虚拟化整个关掉了**，
500 张卡片被全部真实创建出来。当时冷启动 4.7 秒、占 176 MB。

元凶是模板里的 `ScrollContentPresenter` 漏了 `CanContentScroll` 的传递——
没有逻辑滚动就没有虚拟化。系统的默认模板里有这句，自己写模板时极容易漏。

**回归方法**：塞 500 条记录，量冷启动和内存。如果数字随条目数明显增长，就是虚拟化又断了。

## 打包

| 验证项 | 操作 | 期望结果 | 相关步骤 |
|---|---|---|---|
| ⭐ 依赖运行时版 | 双击 `build.bat` | 产物只有一个 exe（约 390 KB），双击能跑 | S21 |
| ⭐ 自包含版 | 双击 `build-standalone.bat` | 产物只有一个 exe（约 162 MB），**没有 .pdb** | S24 |
| 自包含版真的能跑 | 双击 `dist\剪贴板历史.exe` | 托盘出现图标、窗口能开、记录正常 | S24 |
| 自包含版 exe 图标 | 在资源管理器里看 `dist\` | exe 是淡蓝剪贴板图标，不是默认白纸图标 | S19/S24 |
| 自包含版单实例 | 把 `dist\` 的 exe 双击两次 | 不会开出第二个 | S24 |
| 文件属性里的版本 | 右键 exe → 属性 → 详细信息 | 产品版本 `1.0.0`、产品名「剪贴板历史」 | S24 |
| ⭐ 打包脚本认得出"程序在跑" | 开着程序双击打包脚本 | 立刻提示"检测到程序正在运行"，**不是**打到一半才失败 | S24 |
| 换台电脑能跑 | 把自包含版 exe 拷到没装 .NET 的机器 | 双击直接运行，不提示缺运行库 | S24 |

> 自包含版**首次启动会慢一点**（要把原生库解压到临时目录），之后就正常了。
