# 发布打包

> 要打包或分发时读这份。主要在 **S19（图标）** 和 **S21（打包）** 用到。

## 打包前准备

- 确认 `Assets/app.ico` 已就位（托盘和 exe 图标都用它）
- 确认 csproj 里有：
  ```xml
  <ApplicationIcon>Assets\app.ico</ApplicationIcon>
  <AssemblyName>剪贴板历史</AssemblyName>
  <Version>1.0.0</Version>
  ```
- 确认 `docs/06-测试验收.md` 跑完且没有 ❌

## 打包方式

### 方式一：依赖运行时（默认，推荐）

```bat
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

- **产物**：单个 exe，实测约 **385 KB**（会随代码增长）
- **前提**：目标电脑装了 .NET 9 桌面运行时
- **适用**：用户自己的电脑（已装 .NET 9 SDK，向下兼容运行时）

### 方式二：自包含（换电脑用）—— 双击 `build-standalone.bat`

```
dotnet publish -c Release -r win-x64 --self-contained true ^
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true ^
  -p:DebugType=none -o dist
```

- **产物**：单个 exe，实测 **162.6 MB**
- **前提**：无。拷到任何 64 位 Windows 10/11 都能直接双击跑
- **适用**：要给别人的电脑、或对方没装 .NET
- **位置**：`dist\剪贴板历史.exe`

三个参数各有原因，不要随手删：

| 参数 | 为什么 |
|---|---|
| `--self-contained true` | 把 .NET 运行时一起打进去，目标电脑不装也能跑 |
| `IncludeNativeLibrariesForSelfExtract=true` | 把 WPF 的原生 DLL 也塞进 exe。不加的话会散落好几个原生文件在旁边，就不是"单文件"了 |
| `DebugType=none` | 不生成 `.pdb` 调试符号。发布版要的就是"就一个 exe"，旁边多躺一个 .pdb 会让拷贝的人不知道该不该带上 |

> 首次启动会把这些原生库解压到临时目录，所以**第一次打开比平时慢一点**，之后就正常了。

### 产物位置

| 版本 | 位置 | 谁生成 |
|---|---|---|
| 依赖运行时版 | `bin\Release\net9.0-windows\win-x64\publish\剪贴板历史.exe` | `build.bat` |
| 自包含版 | `dist\剪贴板历史.exe` | `build-standalone.bat` |

⚠️ **`dotnet publish` 只写它自己的输出目录，不会管别的。** 实测踩过一次：改完代码只
跑了依赖版的 publish，用户双击的却是 `bin\Release\net9.0-windows\`（上一层的 `dotnet build -c Release`
的产物），于是报"我改了怎么没变"。**改了代码要么跑打包脚本，要么三处都重新编译。**

### 怎么知道用户手上是哪一个

设置窗口底部的**「关于」**会显示版本号和**当前 exe 的完整路径**。
用户报问题时让他截这一块，就能直接看出他双击的是哪一份、什么版本。

## 两个打包脚本

| 脚本 | 打哪个版本 | 产物 |
|---|---|---|
| `build.bat` | 依赖运行时（约 390 KB） | `bin\Release\net9.0-windows\win-x64\publish\` |
| `build-standalone.bat` | 自包含（约 162 MB） | `dist\` |

两个脚本都比最简命令多做三件事：

1. **先删残留的 `ClipboardHistory_*_wpftmp.csproj`** —— 上次构建被中断留下的临时工程会让这次构建
   直接报 MSB1011"有多个项目文件"
2. **检查程序是否还在运行** —— exe 被占用会导致打包失败（MSB3021）
3. 打包完再清一次临时工程

`chcp 65001` 是为了让中文提示不乱码。

> ⚠️ **检查进程那段必须用 `Get-Process`，不能用 `tasklist`。**
> `tasklist /fi "imagename eq 剪贴板历史.exe"` 对**中文进程名会静默匹配失败**——
> 返回空、看起来像"没在跑"，于是打包到一半才报文件占用。
> 同样的坑还害过一次验证：以为程序没启动，其实托盘里挂着一个旧版本，一整轮测试都打在了旧代码上。

## 开机自启是怎么实现的

**原理**：往注册表 `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` 写一个字符串值，Windows 登录时就会执行它。

```
键：HKCU\Software\Microsoft\Windows\CurrentVersion\Run
值名：剪贴板历史
数据："C:\...\剪贴板历史.exe"       ← 注意路径带空格时要用引号包起来
```

用 `HKCU` 而不是 `HKLM` 的好处：**不需要管理员权限**，且只对当前用户生效。

### 关键注意点

- ⚠️ **必须等打包成 exe 之后才能真实验证。** `dotnet run` 期间 `Environment.ProcessPath` 指向的是 `dotnet.exe`，写进去也是错的。
  → 开发期（S16）只验证"开关状态 ↔ 注册表项"同步正确；真正的重启验证放到 S21。
- 关闭自启时要**删掉这个值**，而不是把它设成空字符串（空值会导致 Windows 尝试执行空命令）。
- 读路径一律用 `Environment.ProcessPath`，不要用 `Assembly.Location`（单文件发布下后者会是空字符串）。

### 路径会自动修正，但这有个副作用

程序每次启动都会对比"注册表里记的路径"和"当前 exe 的路径"，不一致就改成当前的
（`StartupService.RepairIfStale`）。好处是用户把 exe 挪个地方不用手动改注册表。

⚠️ **副作用**：只要开了自启，**从哪个副本启动，自启就指向哪个副本**。
所以开发期间随手双击了一个 `bin\Debug\` 里的 exe，用户的自启就被改到那个构建目录去了，
下次清理 `bin\` 就失效——而且**完全无声**。

**给用户的正确顺序**：先把 exe 放到固定位置 → 从那个位置启动 → 再开自启。

## 图标

- 托盘图标和 exe 图标共用 `Assets/app.ico`
- **`app.ico` 必须包含多个尺寸**：16×16、32×32、48×48、256×256。只有一种尺寸的话，任务栏和资源管理器里会显示模糊
- 想换图标：把新的 `.ico` 文件覆盖 `Assets/app.ico` 即可，不用改代码
- 托盘图标建议在代码里用 `new Icon(stream, new Size(16, 16))` 显式指定尺寸，否则可能取了 256×256 那张，托盘里会糊

## 移植到别的电脑

1. 双击 `build-standalone.bat`（自包含版）
2. 把 `dist\剪贴板历史.exe` 拷过去
3. 双击运行 → 托盘出现图标 → 设置里勾选开机自启
4. 数据是**每台电脑独立的**，存在各自的 `%AppData%\ClipboardHistory\`，不会跟着走

> **先放好位置再开自启。** `dist\` 是打包输出目录，重新打包会先删后建。
> 想长期用，先把 exe 挪到一个固定位置（比如 `C:\Tools\剪贴板历史\`），再在那个位置开自启。
> 挪完不用手动改注册表——从新位置启动时，程序会自己把注册表里的路径改对（见下一节）。

**想要迁移历史数据**：把源电脑的 `%AppData%\ClipboardHistory\` 整个文件夹拷到目标电脑的同名位置即可（图片也在里面）。注意 `index.json` 里的文件路径卡片指向的是源电脑的路径，拷过去后那些卡片会显示为"失效"。

## 卸载

程序没有安装过程（绿色版），所以卸载 = 手动删两样东西：

1. `%AppData%\ClipboardHistory\` 整个文件夹
2. 注册表 `HKCU\...\Run` 下的 `剪贴板历史` 值

设置窗口里可以考虑加一个「彻底卸载」按钮帮用户做这两步（**待办，非必须**）。

## 版本号

- 改 csproj 里的 `<Version>`
- 设置窗口的"关于"里显示它（用 `Assembly.GetExecutingAssembly().GetName().Version`）
- 每次打包发布前记得加一号
