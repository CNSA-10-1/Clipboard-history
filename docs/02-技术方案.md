# 技术方案

> **写任何代码前先读这份。**

## 技术选型

| 项目 | 选择 | 理由 |
|---|---|---|
| 语言 / 框架 | **C# + WPF** | WPF 就是微软官方的 Windows 桌面 UI 框架，天然贴合"Win10 设计风格"的要求 |
| 目标框架 | **net9.0-windows** | 电脑上已装 .NET 9 SDK（版本 9.0.304） |
| 第三方依赖 | **零** | 全部使用 .NET 自带能力。以后用户想自己改代码，`dotnet run` 就能跑，不会卡在依赖还原上 |
| 数据存储 | **JSON 索引 + 图片单独存文件** | 用 `System.Text.Json`；文件人类可读，出问题能直接打开看 |

### 为什么不用别的

| 方案 | 放弃原因 |
|---|---|
| Electron | 打包后约 200MB、常驻内存 120MB+；而这是个整天挂在后台的工具，太重 |
| Python + PySide6 | 电脑上没装 Python（只有 Microsoft Store 的占位符）；界面还要额外写样式表才能像 Win10 |
| Tauri | 需要 Rust 环境，电脑上没有；对非程序员用户后续维护门槛高 |

## 零依赖是怎么做到的

| 需要的能力 | 用什么实现 |
|---|---|
| 剪贴板变化监听 | Win32 `AddClipboardFormatListener` + `WM_CLIPBOARDUPDATE` 消息，挂在**隐藏的消息窗口**上，所以主窗口关掉也照常记录 |
| 托盘图标 | `System.Windows.Forms.NotifyIcon`（属于 `Microsoft.WindowsDesktop.App` 共享框架，.NET SDK 自带，**不需要 NuGet**） |
| 数据序列化 | `System.Text.Json` |
| 开机自启 | 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，不需要管理员权限 |
| 深色模式检测 | **每次显示窗口时**读一次注册表 `HKCU\...\Themes\Personalize\AppsUseLightTheme`。这样就不用引入 `Microsoft.Win32.SystemEvents` 这个 NuGet 包 |

> csproj 里需要 `<UseWindowsForms>true</UseWindowsForms>`（为了 NotifyIcon），同时保持 `<UseWPF>true</UseWPF>`。两者可以共存。

### ⚠️ 但必须关掉 WinForms / Drawing 的全局 using

开着 `UseWindowsForms` 时，SDK 会**自动全局引入** `System.Windows.Forms` 和 `System.Drawing`，
而它们和 WPF 大面积撞名——`Application`、`Clipboard`、`DataObject`、`Color`、`Brush`、`Pen`、
`Point`、`Size`、`Font`、`Timer`、`Keys`……第一个撞上的就是 `App.xaml.cs` 里的 `Application`，
直接编译不过。

所以在 csproj 里显式移除这两个全局引入：

```xml
<ItemGroup>
  <Using Remove="System.Windows.Forms" />
  <Using Remove="System.Drawing" />
</ItemGroup>
```

需要托盘图标的 `TrayService.cs` 里再单独 `using System.Windows.Forms;`，冲突的类型就地起别名。

## 数据流向

```
用户复制内容
    ↓
Windows 广播 WM_CLIPBOARDUPDATE
    ↓
ClipboardMonitor（隐藏窗口收到消息）
    ↓ 按 文件 → 图片 → 文字 的顺序取第一个非空的
    ↓ 检查是否是自己刚写回去的（序列号比对）——是就丢弃
    ↓
StorageService.Add()
    ↓ 算内容指纹 → 已有相同内容？→ 更新时间并移到顶部（不新增）
    ↓ 否则新建条目，图片写入 images/ 并生成缩略图
    ↓ 原子写入 index.json
    ↓
MainWindow 列表刷新
```

写回时反向走一遍：`点击卡片 → ClipboardWriter → 写剪贴板 → 记下序列号 → 窗口隐藏`。

## 关键实现要点（最容易踩坑的地方）

1. **不要记录自己写回的内容**
   点卡片会写剪贴板，这又会触发一次变化事件，导致历史里自己刷自己。
   → 写入后用 `GetClipboardSequenceNumber()` 记下序号，下一次事件序号相同就跳过。

2. **剪贴板被占用会抛异常**
   别的程序正持有剪贴板时，读写会抛 `COMException`（HRESULT `0x800401D0`）。
   → 所有剪贴板操作统一包一层"重试 3 次、间隔 50ms"的辅助方法，不允许裸调用。

3. **图片不要锁住文件**
   加载缩略图时如果用默认方式，图片文件会被 UI 占用，之后删除和清理都会失败。
   → 一律用 `BitmapCacheOption.OnLoad`，并且在同一个 `using` 里把 `Stream` 读完。

4. **列表性能**
   → 图片卡片只加载缩略图（长边 ≤ 200px，生成时用 `DecodePixelWidth` 省内存）；
   → 原图只在真正写回剪贴板时才读；
   → 列表用虚拟化（`VirtualizingStackPanel`）。

5. **一次复制可能带多种格式**
   比如从浏览器复制图片，同时有图片格式和文字格式。
   → 按 **文件 → 图片 → 文字** 的顺序取第一个非空的。
   → 明确**忽略 `HTML Format`**，保证不会存进富文本。

6. **单实例**
   → 命名 Mutex（`Global\ClipboardHistory_SingleInstance`）防止开两份互相抢剪贴板。第二份启动时直接把已有窗口呼出来然后自己退出。

7. **开机自启写的是 exe 的路径**
   → 这个功能必须等**打包成 exe 之后**才真正生效，`dotnet run` 期间写进去的是无效路径。
   → 开发期只在设置界面验证"开关状态和注册表项同步"，真正的自启验证放到 S21。

8. **文件卡片可能失效**
   文件被移动或删除后，卡片还在但路径没用了。
   → 卡片上把文件名显示为灰色并加标记；点复制时给出提示。

9. **索引写入要原子**
   写入过程中崩溃会把整个索引写坏。
   → 先写 `index.json.tmp`，再用 `File.Replace` 替换（保留 `.bak`）。

10. **剪贴板里可能有 .NET 序列化对象——读它会崩**
    别的程序（尤其是 .NET Framework 写的）可能往剪贴板放一个二进制序列化的对象。
    WPF 读到这种内容会调 `BinaryFormatter` 去反序列化，而 **.NET 9 已经把它移除了**，
    于是抛 `PlatformNotSupportedException`。

    这不是 `COMException`，普通的重试封装接不住；它从剪贴板监听的回调里逃出去，
    一路穿过消息循环，**整个程序当场崩溃**——而且崩的时候你可能根本不在电脑前。

    三层防线，缺一不可：
    - `ClipboardRetry` 的每个方法都要有兜底的 `catch (Exception)`，非时序类的错误直接放弃这条内容
    - `App.OnClipboardChanged` 最外面再包一层 try/catch
    - `App.InstallCrashGuards()`：界面线程和后台上线程的未处理异常都记日志、保住进程

    同理，`ClipboardCapture.ReadBitmaps` 里读原始剪贴板对象的那条"多图"路径必须允许失败，
    失败就退回去走标准的单图路径，不能因为一次坏数据把整次复制丢掉。

11. **列表视图要用 `GetDefaultView`，别自己 new `CollectionViewSource`**
    踩过的坑：用 `new CollectionViewSource { Source = ... }.View` 拿到视图、给它设了 `Filter`、
    把列表绑上去——然后改 `GroupDescriptions`（搜索时要隐藏分组），
    `CollectionViewSource` **会换一个 View 实例**。结果就是"我给 A 设了筛选，列表却绑在 B 上"，
    输入关键词完全没反应，而且不报任何错。

    正确做法：
    ```csharp
    _itemsView = CollectionViewSource.GetDefaultView(collection);
    _itemsView.Filter = ...;
    _itemsView.SortDescriptions.Add(...);
    list.ItemsSource = _itemsView;
    ```
    默认视图是每个集合唯一且稳定复用的，排序、分组、筛选都在同一个对象上生效。

12. **托盘常驻的三件必做事项**
    - **`ShutdownMode` 必须是 `OnExplicitShutdown`**。默认的 `OnLastWindowClose` 会在主窗口一关就结束进程——
      而托盘程序关窗口只是"藏起来"，进程必须活着继续记录。
    - **关窗口 ≠ 退出**。在 `MainWindow.OnClosing` 里判断 `App.IsExiting`：没在退出就
      `e.Cancel = true; Hide();`。真正的退出只有托盘菜单里的那一项。
    - **关掉窗口时别最小化，要 `Hide()`**。最小化会在任务栏留一个按钮，而这是个托盘程序，
      收起之后任务栏再杵着一个图标很碍事。

13. **单实例怎么做**
    命名 `Mutex`（`Local\...`，只对当前登录会话唯一）判断自己是不是第一个实例；
    不是的话，通过一个命名 `EventWaitHandle` 通知已有实例"把窗口显示出来"，然后自己退出。

    **守卫必须放在最前面**，早于 `Storage.Load()`：两个实例同时写 `index.json` 会互相覆盖，
    轻则重复记录重则把历史写坏。

    另外，互斥体创建失败（权限问题）时应该**放行**而不是拒绝启动——
    不能因为"守卫本身出问题"就让用户彻底用不了软件。

14. **相对时间的刷新**
    "3 分钟前"会随时间变化。
    → 窗口显示时刷新一次；窗口可见时每分钟刷新一次；窗口隐藏时停掉定时器（省电）。
