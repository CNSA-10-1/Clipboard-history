### 以后端到端验收时必须重点回归的两条

- ⚠️ **`index.json` 读写要保证不丢数据**。S7 期间踩过一次：改了 JSON 字段命名策略后，
  旧存档解析成 0 条，界面上看着像"历史没了"，而下一次复制就会拿空列表覆盖存档。
  已加两道防线（读时大小写不敏感、解析不出版本号就留档不覆盖），S20 要专门回归这条。
- ⚠️ **DLL/exe 被上一次运行的进程占用会导致构建失败**。构建前先确认程序已退出。

### S25 的取舍：自包含版要不要开压缩

实测三版对照：

| 版本 | 磁盘 | 冷启动 | 常驻私有内存 |
|---|---|---|---|
| 依赖运行时版 | 0.4 MB | 1.19 s | 56 MB |
| 自包含 · 未压缩 | 146.5 MB | 3.39 s | 58 MB |
| 自包含 · 压缩 | **65.6 MB** | 4.62 s | **122 MB** |

- **去掉 12 种多余语言资源是纯赚的**（162.6 → 146.5 MB，没有代价），这条已经保留在 `csproj` 里
- **压缩再省 81 MB 磁盘，但换来 +1.2 秒启动和 +65 MB 常驻内存**（验证过，不是临时开销）
- 冷启动对托盘程序影响有限（只在开机那一次），所以关键看那台电脑的**内存**够不够

**`build-standalone.bat` 里现在还带着压缩参数。** 如果决定不要压缩，删掉
`-p:EnableCompressionInSingleFile=true` 这一项即可。

> 唯一能进个位数 MB 的路是移植到 .NET Framework 4.8.1（框架随 Windows 走），
> 但要换掉 `System.Text.Json`（.NET Framework 不自带）、失去单文件打包、99 条验收全部重跑。

### 开机自启的注册表现在指向 `dist\` —— 需要你把 exe 挪个地方

`StartupService` 的"自启路径自动修正"是**按设计**工作的：从哪个副本启动，自启就指向哪个副本。
这一轮验证时启动过 Debug 版和 `dist\` 版，注册表就跟着改了几次，**现在指向**：

```
HKCU\...\Run\剪贴板历史 = "C:\Users\<用户名>\Desktop\历史粘贴\dist\剪贴板历史.exe"
```

`dist\` 是打包输出目录（`build-standalone.bat` 会先删后建），当"长期住址"不合适。

**推荐做法：**

1. 把 `dist\剪贴板历史.exe` 复制到一个固定位置，比如 `C:\Tools\剪贴板历史\`
2. 从**那个** exe 启动（自启路径这时会自动改对，不用手动改注册表）
3. 托盘右键 → 设置 → 检查"开机自动启动"是开着的 → 保存
4. 重启电脑，确认托盘里有它

> 设置窗口最底下的「关于」会显示**当前这个 exe 的完整路径**，可以拿它核对第 2 步有没有生效。
